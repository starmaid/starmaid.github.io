## Getting Started

Mimi from ebro came to our discord server with the proposition to gather all of these talented artists and writers, and make a video game. Gamejams are a good way to get a game DONE instead of just throwing some ideas with no set goals together, and the themes and style restrictions give just enough to let artistry and ideas flow easily. E was the foremost expert, having done several gamejams with other people in university, and was willing to coach some of us through the process. This jam ran from August 4th to September 4th, so a full month gave enough time for the members who have full-time jobs could contribute sizable portions in the evenings and weekends. 

![idk maybe a discord screenshot? maybe a miro board screenshot?]()

I was super excited to work with talented artists so i was happy to take a vision backseat and focus on tools and game building. We did an ideation session, where everyone threw some ideas around, and we settled on using Unity to make a RPGMaker-style game, and some basics for the story and where the horror comes from.

## Training

This was most people's first time ever working on a video game, and some people's first time ever working on a programming project at all. As such, over a month before the start date we held short classes on how to use some various tools once a week.

- Miro canvas basics
- Unity basics
- Github and git basics
- Github project management basics (we ditched this and just moved cards around in Miro)
- Ink dialogue system basics

Also for a gamejam, we are allowed to do ideation and concept design before the start - so various artists worked on style tests, sketches, scene descriptions, etc. I also used some of this time to learn the differences between Unity and the only game engine I had used until then, Unreal Engine 4.

It became clear that many people on the project loved the project management aspect of it. We did probably spend too much focus on the tools and process, but it was a huge learning experience. 

## The Jam

Obviously with 6 main members and a few additional helpers, there were a lot of cool things done by the team. I'll use this blog post to summarize things that I did that I think were cool.

### Google Drive-Github Tooling

For 3/6 members of the team, this was their first time using Git. Additionally, tracking binary blobs for photoshop files and audacity projects did not seem like a useful way to track them. So as a compromise, I set up a Google Drive folder that each artist synced to their own computers using Google Drive Desktop, and then I could extract their exported files into the game assets folder, and all the programmers would get updated assets to work with. 

![some picture that evokes the script]()

*See the file on [Github](https://github.com/starmaid/augmented-gem/blob/main/sync.sh)*

To make sure the artists were dividing and conquering the large list of sprites and sound effects, after a brainstorming session I created an asset manifest spreadsheet that contained priority and assignee and even dates, progress, and other notes. I had just seen this spreadsheet format at my job at SRI, where Alison was leading an effort for my team to prepare source code and other assets for delivery to a startup. The art team took it and ran, adding cool formatting and stuff.

![asset manifest]()

### Github Unity Build Pipeline

I set up the game-ci github action to build the game for multiple platforms, including webGL. This made builds reproducible and easy to track. I didn't author the workflow, but this was my first time setting one up and using it. I had to learn about triggers and secrets and all the things that make the machine work. I also used branch protection and PR checks, so breaking `main` was now at least checked from a compilation standpoint.

![screenshot of the actions runner page, or maybe a release with assets?]()

Funnily, when writing this post, I went back to check on those actions - and the record had all been deleted because Github only keeps records from within the past year. The assets had been purged too, and I never actually created a "Release", instead just making tags and then going to the artifacts page and downloading them. The tags are still there, but I went back and updated the workflows so they could run today (and I could get this screenshot).

### Shaders

I worked on some shaders to make the game pop. I followed acerola's dithering shader for my own implementation in unity's shadergraph implementation.

I also added a flickering glow shader for candles and electric lighting.

I made sure the downsampling filter was clean for the whole scene to give it a bit of a pixelly look. This was coordinated with canvas size rules for the artists.

Getting the text to render properly was another challenge.
